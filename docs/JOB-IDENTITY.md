# v1.1.6 岗位身份与分别追踪

负责方：本监督任务，继续唯一维护副本。未改真实数据、已发布包或预填功能。

## 已修缺口

旧手动入库按公司＋招聘编号去重，没有来源范围；不同招聘板复用编号会更新同一条。投递台账按公司＋编号（无编号时按标题＋地点）唯一，导致不同岗位无法分别记录。

公开招聘源已有 provider/board/有效 API 岗位 ID，继续以来源和 ID 更新；同名同地点不同 ID 分别保留。同源岗位更新不发新岗位提醒，下架再出现只发一次重新开放提醒。

手动草稿的编号仅在原页面范围内有效：身份包含去明确跟踪参数后的 URL 和编号。无编号时仍需同一页面、公司、标题、地点一致才复用。不同页面只有标题/地点/文案相似，不合并。保留功能查询参数（例如 job=1 与 job=2 不同），仅去明确广告参数与片段；不推断重定向、镜像页或改址后的同一岗位。跨板复用编号分别保留。

同公司同名同地点或编号重复的条目显示“相似岗位或编号重复，已分别保留”以及相关条目编号；可查看原职位链接和职责摘要再分别记录。此提示不认定它们相同，不自动合并、删除或覆盖。

## 投递关联与兼容

明确点击“存到投递台账”后按岗位条目建立独立投递身份；关联放在现有 settings 表。重复点击返回原投递记录，不重置面试、关闭等状态。分别编辑 A/B 不串状态。无需新增列或迁移表结构。

旧投递记录仅在公司、编号和规范化页面一致、且唯一且未关联别的条目时复用；无编号还需标题和地点一致。无法证明的旧记录保留，不凭标题或编号猜测关联；可能需要人工核对。多条旧投递同时匹配则明确失败而非任选。旧手动岗位只在重新确认相同身份时更新历史 source_id，保留其数据库 ID。历史上已经被旧版覆盖丢失的信息无法自动复原。
