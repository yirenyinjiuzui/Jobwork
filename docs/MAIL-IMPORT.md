# v1.1.2：本地邮件双正文与判断证据

修复场景：multipart/alternative 的纯文本只有“请勿回复”等页脚，实际岗位与终止通知在 HTML。现在分别读取当前邮件的纯文本、HTML 可见文字与主题，不再让纯文本优先规则漏掉 HTML 决定。预览仍不修改记录。

## 如何使用

在投递追踪中选择本机 .eml，点“解析并预览”，展开“判断证据”。每条证据标注“纯文本正文 / HTML 正文 / 邮件主题 / 手动提供”，显示公司、岗位、编号或状态的原文片段。核对建议岗位与状态，再点“确认写入”；未确认不保存。

若正文状态冲突、只知道雇主、不清楚具体岗位、编号与岗位名矛盾，或同名岗位不唯一，不预选记录和状态。你须选择目标岗位并勾选“我已核对正文冲突、身份与所选岗位”。保持“不变更”只记录待核实历史，所有投递字段保持原样；明确选择状态才会尝试更新，既有旧通知/状态倒退保护仍然有效。已留存的同一邮件不会重复导入，之后需更正时可在台账编辑记录。

匹配建议只来自当前通知范围的明确公司及岗位编号，或唯一且完整一致的公司＋岗位名。不从发件人邮箱、推荐岗位、链接、跟踪参数或散落的 JR 编号猜身份，不展开 SWE 等岗位缩写。“可信范围”指当前通知文本中的明确身份字段，并不代表认证了发件人真实性。

HTML 不渲染：不加载 URL、远程图片、脚本或样式；忽略附件、链接文字、隐藏元素与识别出的引用历史，识别出的推荐区及其后内容不参与判断。链接和常见跟踪参数不进入证据。特殊模板、岗位只在链接/图片里、未识别出的推荐标题、复杂转发、多正文结构或自然语言仍可能无法可靠识别，需手动核对；这不是任意邮件的语义理解或真实性验证。

## 全部虚构的验收样例

无需接入邮箱。自动测试已在临时库完成下列流程；附带三封 .eml 仅供可选本机复现。

1. 使用独立库 `.\start-windows.cmd --data data\mail-acceptance.sqlite3 --interval 0`，避免触碰正式库。
2. 建立虚构公司 `Fictional Harbor Labs` 的两条记录：A 为 `Data Intern / FA-1001 / 已投递`；B 为 `Systems Graduate / FB-2002 / 面试`，面试时间 `2026-12-02 14:00`。
3. 导入 [html-decision.eml](mail-fixtures/html-decision.eml)：纯文本只有页脚；HTML 包含 A 的身份与 `Your application was unsuccessful.`。应建议 A、流程终止。预览后两记录不变；确认后仅 A 终止，B 面试和日期不变。
4. 导入 [mime-conflict.eml](mail-fixtures/mime-conflict.eml)：纯文本确认面试，HTML 表示终止。应显示冲突证据，不预选岗位、状态；不勾选复核不能提交。选 A 并勾选但不选新状态，只增加历史。
5. 导入 [generic-review.eml](mail-fixtures/generic-review.eml)：雇主级审核通知，推荐区含 A 编号。不得据此建议 A 或 B；需复核。

## 已验证与未验证

自动化覆盖 MIME 两种顺序、主题冲突、不同岗位/编号冲突、唯一同名与重复同名、缩写/泛称、推荐区/链接/附件/散落编号、发件人不能补公司、中英文和 HTML 表格、隐藏内容、脚本/远程图片不执行、对外 socket 禁用、A/B 数据隔离、服务端复核门槛，以及模拟 DOM＋真实 HTTP 的文件选择和确认流程。

真实 Windows 启动、PowerShell TXT 恢复、Chrome/Edge 扩展工具栏仍未实机验证。没有读取真实邮箱、身份、简历或凭据，没有登录或投递。本轮只修本地邮件导入，不改变发现源和浏览器提交边界。
