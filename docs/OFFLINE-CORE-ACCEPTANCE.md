# 一条离线验收：发现 → 确认预填 → 跟踪

负责人：本监督任务。版本 v1.1.8 候选。所有样例均虚构；不需要真实招聘网站、邮箱或申请资料。

## Windows 手工照做

1. 把新包解压到新的 D 盘目录，保留旧版和数据。在该目录打开终端，运行一次 `start-windows.cmd --data data\core-loop-01.sqlite3 --interval 0`。先确认这个演练库不存在；重复演练换 02 等新文件名，不删旧文件。浏览器访问启动窗口所示本地地址。
2. 在岗位发现新增来源：公司填 `Fictional Core Loop`，平台选离线演示/demo，板代号 `core-loop`。连续检查两次：第一次建立基线，第二次出现 `Agent 应用开发实习生 / AGENT-03`。筛选“全部”查找此编号，明确点击“存到投递台账”。未点击前不应出现对应投递。
3. 打开本地 `http://127.0.0.1:8765/demo-form.html`。按 extension/README.md 加载扩展，导入 extension/demo-profile.json。点击扫描/预览：字段必须仍为空；核对所选姓名和邮箱后明确确认预填：值出现。练习表单不提交；不输入任何真实资料。
4. 回到刚建立的同一投递，状态改为已投递，实际投递时间填 `2026-11-01 10:00`。打开导入通知，依次选择 `tests/fixtures/core-loop` 中以下 .eml；每次先看证据，再确认写入。

|文件|操作与预期|
|---|---|
|01-invitation.eml|确认原邀请；测评编号 LOOP-TEST-1，截止 11 月 3 日 18:00 香港，精确时间。|
|02-extension.eml|预览不改数据；未勾选同一测评确认不能更新。核实来源、发送时间及编号后勾选并确认，截止估算为 11 月 5 日 10:00。|
|03-extension.eml|再次单独确认；截止估算为 11 月 6 日 10:00。不得显示为精确截止。|
|重复 03，再导入 02|不增加重复历史、不漂移回旧截止；11 月 6 日 10:00 保持。|
|04-unknown.eml|缺测评编号，手选同一记录并勾选复核，仅留历史，不改截止。|
|06-different-test.eml|不同测评编号，复核后仅留历史，不改截止。|
|05-interview.eml|确认后状态为面试，预约 11 月 10 日 14:00；原测评邀请与延期历史仍可查看。|

样例采用固定 2026 年日期，所以今天看可能已过期；不应为了演练改电脑时间。完成后关闭演练服务，保留该库；正常双击启动仍使用默认正式库。上述步骤在真实 Windows/Chrome/Edge 仍待验收，不把自动化结果视为实机通过。

## 维护方可重复自动化

在项目根目录运行 `node --test tests/test_ui.mjs`（仅维护测试需要 Node；日常软件仍只需 Python 标准库）。测试自动使用临时 SQLite、临时端口和离线 demo，结束清理临时库，不读取默认 data。成功应出现 `CORE LOOP PASS`。

同一测试中：新岗位提醒 → UI 明确收藏 → 读取本地 HTTP 练习 HTML 的字段标签 → 原有扩展扫描/预填引擎 → 明确确认才填、提交调用数为 0 → 同一 application_id 的原邀请、两次延期、重复/乱序、不明编号、面试与历史证据。网页与扩展 DOM 是共享模拟器；HTTP、Python、SQLite、邮件 MIME 解析及扩展业务函数实际执行。这个测试不验证浏览器工具栏和操作系统权限。

完整回归：`python -B -m unittest discover -s tests -q`，以及 `node --test tests/test_extension.mjs tests/test_capture.mjs tests/test_popup.mjs tests/test_ui.mjs`。本轮 123 + 32 = 155 项通过。

## 实质修复与边界

复现了无测评编号/无单独确认的两封 48 小时提醒直接覆盖截止的问题。现从当前邮件文本提取显式 Assessment ID / Test ID / 测评编号，显示有限原文和来源；相互冲突、编号缺失或发送时间不明都复核。测评身份保存在已有 settings 中，不改表结构。不同岗位或不同测评不共享身份。

邮件相对测评期限需明确勾选来源、发送时间和同一测评确认；每封新的延期分别确认。旧测评没有可信编号时不自动补认，复核留历史后可在台账手动核对具体安排。邮件 Date 不是认证签名，也不是实际收件时间；人需核实来源和计时起点。“收到后 48 小时”不等同于发送后 48 小时，推算一律标估算。此轮保护针对 .eml 测评邮件；不能把粘贴不明正文当作已验证测评证据。

原邀请不被删除；新的估算按各自通知时间计算，重导入指纹去重，未处理过的旧延期也只留历史。只有确定有实质修复才建立 v1.1.8；旧包、默认数据保持不动。无上传。下一验收点是上述单条 Windows 虚构流程。
