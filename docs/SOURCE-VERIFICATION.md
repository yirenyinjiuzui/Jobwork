# v1.1.10 来源缺席与关闭证据

负责方：原监督任务。沿用 v1.1.9 唯一维护副本，仅使用虚构来源、临时数据库与本地 HTTP。

## 独立复现

已建立基线的公开来源有 1 个开放岗位。下一次返回格式正确的空列表，旧版立即写 active=0、报告 closed=1，即使没有任何关闭证据。超时与 HTTP/解析异常已有保留旧记录的保护，但岗位行没有明确显示本次不能核实。

## 本轮修复

公开来源返回空列表、或部分岗位缺席时，不再由“未返回”推断关闭。保留最后 active 状态和原岗位内容，标注“本次暂不可核实”，展示最后记录状态及上次接口看到该岗位的时间。首次就为空也不建立“未开招”的基线。请求错误保留岗位；超过 24 小时没有接口观察、或旧记录未记录观察时间，同样标注不确定。这是本地观察新鲜度提示，不代表招聘方认证。

正常返回恢复后清除不确定状态，不制造关闭再开放的虚假提醒。网络较慢的旧请求结果不能覆盖较新的尝试；每次新检查会使旧的关闭确认令牌失效。缺席的旧快照同样只能触发复核，不能自动关闭缺失岗位。

保留真实关闭路径：在待复核岗位点“职位详情”，只有原招聘页明确说明已关闭/停止接受申请，才点“核对原页后确认关闭”并确认。接口超时、空列表、打不开或登录墙都不是关闭证据，不要点确认。确认绑定该岗位、原链接及当前检查令牌，记录人工核实原因和时间。每次确认的原始记录在现有 settings 中独立保留，岗位行显示最近一次核实证据；不改投递状态、历史或申请关联。后续正常接口再次返回该岗位仍可走原重新开放提醒。

API `/api/job/confirm-closed` 要求 reviewed=true、当前 token、原岗位 URL 和非空原因；无明确确认、错误链接、过期令牌或重复确认均失败。服务不自动访问或判断招聘页内容，证据是用户核实声明。

离线 demo 的有意关闭仍按既定虚构阶段执行；它不是外部接口可信性的示范。真实公开源采用上述保守缺席规则。

## 兼容与验证

无新表或列，新增观察/复核信息放在既有 settings。旧库读取不改写岗位、投递、原历史；没有观察时间的旧岗位显示未知。既有关闭记录仍保留，不擅自恢复；旧版已经误关的记录无法自动断定。

完整回归 Python 141 + Node 32 = 173 项通过。新增 9 项覆盖空列表、首次空、超时/请求/解析错误、旧快照缺席、观察过期、确认关闭/重新开放、过期确认、较旧并发请求及端到端 HTTP。既有岗位身份测试改为先明确核实关闭再验证重新开放；不再把第一次空列表当作可信基线。新包解压、归档 v1.1.9 合成旧库结果见成品 FINAL-VERIFICATION.txt。

可重复离线运行 `python -B -m unittest discover -s tests -p 'test_source_verification.py' -v`。HTTP 场景包含在 tests/test_server.py；全部使用注入的虚构来源，不连接招聘网站。预填及测评核心闭环继续通过。

## 用户验收与边界

在隔离演练库中观察：暂不可核实时仍看到最后开放记录，未自动关闭，既有投递不变；再次检查成功后恢复普通显示。只有人工核实了原页明确关闭，才点关闭确认。自动化的 HTTP 夹具无需用户访问真实招聘页。

未知的服务端缓存没有可靠版本/时间元数据时，不能证明接口内容实时。此版保障“缺席不自动关闭”，不会宣称识别了所有旧缓存。24 小时只是本地观察提示；它不会自动下架岗位。

真实 Windows、Chrome/Edge 工具栏未实测。本轮为 Linux 合成数据、模拟 DOM、真实本地 HTTP/SQLite；没有登录、投递、上传或读取真实资料。下一验收点是 Windows 上检查不确定状态显示与人工关闭确认界面，仍用隔离虚构数据。
