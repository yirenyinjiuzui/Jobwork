# Windows 安装、恢复与首次验收

## 正常 ZIP 路径

1. 安装 Python 3.11 或更新版本；安装时勾选 Add python.exe to PATH。已安装无需重复安装。重新打开 PowerShell，用 `py -3 --version` 或 `python --version` 确认。
2. 将 ZIP 完整解压到 D 盘一个**新的空文件夹**。不要在压缩包预览里双击启动。打开解压后真正包含 `start-windows.cmd` 的 `job-workbench` 子文件夹。
3. 双击 `start-windows.cmd`，保留命令窗口；访问 http://127.0.0.1:8765/ 。未自动打开浏览器可手动输入此地址。

## ZIP 下载一直转圈：现有 TXT 备份

TXT 与 ZIP 包含相同发行内容，不是另一个版本。保存完整 TXT 到本机，打开它并复制开头标注的 PowerShell 恢复命令（不复制后面的 Base64 数据），粘贴到 PowerShell 执行。按提示输入 TXT 完整路径，以及一个不存在的新目标文件夹，例如 `D:\JobWorkbench-test`。路径可以有中文和空格。

命令先读取标记间的 Base64，校验 SHA-256，成功后才创建新目录、写入 ZIP 并解压。目标已存在时直接停止，不会覆盖任何现有 `data`；校验失败时不会创建目标。恢复中途失败留下的新目录不要与旧项目混用，保留错误信息并换一个新目标重试。无需修改 PowerShell 执行策略、管理员权限或联网。此版本 TXT 带说明和校验信息，**不要再对整个 TXT 直接执行 FromBase64String**。

如果已经有可用 ZIP 或完整解压目录，直接使用，不必再还原一遍。下载故障本身不代表程序文件损坏。

## 不碰正式数据的首次试用

在包含启动脚本的文件夹打开 PowerShell，运行：

```powershell
.\start-windows.cmd --data data\acceptance.sqlite3 --interval 0
```

加载演示记录并检查演示来源三次，应依次看到基线、新岗位、重新开放。关掉服务，再执行同一命令，确认记录保留。此路径与默认正式库 `data/workbench.sqlite3` 分开；若已有同名试用库，可把 acceptance 改成新的名字。结束后关闭服务，普通双击启动即回到正式库。

Chrome/Edge 扩展只需选择常用的一款，按 [扩展说明](../extension/README.md) 加载本目录 extension，用 demo-profile.json 和本地练习表单验证。扩展工具栏权限与 D 盘实机运行尚需 Windows 验收；云端测试无法替代。

## 常见问题

- 找不到 Python：安装 3.11+ 并重开窗口。启动器先尝试可用的 `py -3`，再尝试 `python`，不会继续用过旧版本启动。
- Incomplete extraction：完整解压整个 ZIP 到新目录，不要只复制启动脚本；错误文字会列出缺失文件。
- 端口占用：先关闭旧工作台；或运行 `.\start-windows.cmd --port 8766`，访问 http://127.0.0.1:8766/ ，并同步修改扩展中的端口。
- 无写入权限：选自己有写权限的 D 盘目录。不要通过删除原有 data 解决问题。
- 招聘源超时：此次维护将总时限提升至 30 秒；网络异常仍可能失败，失败会保留旧清单。复制错误文字和公开招聘板网址即可交给维护方定位。

## 已有数据升级：独立快照（v1.1.5）

程序 ZIP/TXT 恢复只还原软件，**不会备份你的投递数据库**。不要在运行期间只复制 `workbench.sqlite3`：已提交记录可能还在 WAL 旁文件中。

1. 将新版完整解压到新的 D 盘目录，例如 `D:\求职工作台 1.1.5\job-workbench`，先不要启动新版。停止旧服务及计划任务，避免快照之后继续产生新记录；保留整个旧安装。
2. 用资源管理器创建 `D:\求职备份`。双击**新版目录**的 `data-tools-windows.cmd`，输入 `1`；来源输入旧版实际数据库完整路径（默认是旧版 `data\workbench.sqlite3`）；目标输入一个从未使用的名字，例如 `D:\求职备份\升级前 [01].sqlite3`。若以前使用 `--data`，必须选那个实际库。
3. 只有显示 `SUCCESS`、`integrity_check=ok`、`foreign_key_check=ok`、`workbench_schema=ok` 才算完成。窗口同时显示新文件完整路径、`Applications` 投递条数、`Jobs` 岗位条数、SHA256。窗口按键关闭前可复制这些结果；原库和原备份均不会被覆盖。目标或其 SQLite 旁文件已存在会明确失败，请换新名字，不要删除原文件。失败或中断后没有成功结果的文件不可用，换新目标重试。
4. 在新版目录用资源管理器创建空的 `data` 文件夹。再次双击 `data-tools-windows.cmd`，输入 `2`；来源为刚才的备份，目标为 `D:\求职工作台 1.1.5\job-workbench\data\workbench.sqlite3`。目标必须不存在。还原也会独立回读校验，核对投递/岗位条数与备份结果一致。
5. 双击新版 `start-windows.cmd`，核对岗位和投递记录后再继续使用。旧版保持关闭；需要回退时保留新版数据，勿用旧备份覆盖已有新记录。如两边已有记录，停止自行复制或合并。

全流程不需 PowerShell、管理员权限、执行策略修改或额外依赖。工具支持含中文、空格、方括号的路径。快照是完整数据库（包括配置、历史记录），并不复制数据库外的附件或其他文件；旧目录仍应保留。活跃 WAL 连接下的已提交数据可安全进入一致快照，未提交事务不会进入；升级时仍推荐先停止服务，以免快照后新增数据遗漏。

命令行备用用法（不必与双击流程重复执行）：

```text
python data_snapshot.py backup "旧库完整路径" "不存在的新备份完整路径"
python data_snapshot.py restore "备份完整路径" "不存在的新库完整路径"
```

来源不存在不会新建空源库。目标父目录必须先创建。`restore` 同样通过 SQLite Backup API 生成新库，不替换现有库、不迁移表结构。忙碌超时或校验失败返回非零退出码，不报告成功。真实 Windows CMD/PowerShell 5.1、D 盘及扩展工具栏尚未实测；Linux 自动化不是 Windows 实测。

本候选基于可核验旧包重建恢复校验，并加入端口占用时不打开数据库的保护。详见 [来源、恢复和启动验收](BASELINE-RECONSTRUCTION.md)。端口冲突请核对原服务路径，勿终止不明进程或把任意 HTTP 200 当本次启动成功。
