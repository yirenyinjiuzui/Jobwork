## 恢复保护已重建

SQLite 完整不等于工作台可用。独立快照关闭回读后检查 7 张关键表、列类型/默认值/主键、唯一与外键约束；拒绝关键表被视图/虚表替代、未知触发器及不可读 date_precision JSON。允许已支持旧版缺 resume_label/submitted_at，保留原结构，由正常启动逻辑补齐；校验不迁移来源。

只有 `SUCCESS` 且 `integrity_check=ok`、`foreign_key_check=ok`、`workbench_schema=ok` 才可启动新安装。任何已有目标都拒绝覆盖；失败只清理本次新目标，来源和当前可用数据库保留。此校验不证明业务内容真实，也不自动修复陌生数据库。程序 TXT 解包不是数据库恢复。

## 启动保护

已复现旧版在端口冲突时返回失败，却提前创建或迁移指定数据库。现先绑定本轮监听，再打开 Store；占用端口时不打开数据库或浏览器，不探测任意 HTTP 200、不关闭其他服务、不自动换端口或数据库。当前项目没有 PowerShell HTTP 健康探针，原本也未在端口冲突后打开浏览器，不能把这两项说成已复现故障。

数据库初始化失败时释放本轮监听；正常首次启动、重启及明确另开端口/数据库仍可使用。Windows 分支配置 SO_EXCLUSIVEADDRUSE 防止竞争监听，但只有分支模拟测试，不是 Windows 实测。

Windows 正常双击 start-windows.cmd。冲突时看错误窗口并核对已有启动窗口中的数据库路径；如确需另开隔离库，明确运行 `.\start-windows.cmd --port 8766 --data data\separate-demo.sqlite3 --interval 0`，并让扩展使用对应端口。不要凭浏览器某端口能打开就认定本轮启动成功，不终止不明进程。

## 验收与限制

恢复：伪同名表、缺历史/约束、JSON 异常拒绝；来源及当前库不变；活跃 WAL、未提交隔离及中文空格方括号路径继续通过。
启动：合成任意 HTTP 200、旧工作台同库/异库占用均未调用 Store；原服务继续响应；初始化失败释放端口；真实本地首次启动与重启读写通过。
