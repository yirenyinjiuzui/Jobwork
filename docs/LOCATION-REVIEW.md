# v1.1.4 候选：香港实习地点证据与复核

## 解决的实际问题

旧流程只凭结构化地点分类。虚构岗位的标题与地点均写 Hong Kong，正文却写 “The internship is based in Singapore. After graduation the permanent role is in Hong Kong.”，旧版仍归入香港实习。浏览器草稿原本不传正文，主程序也无法看见冲突。

本轮沿用同一维护副本，选择“浏览器草稿 → 人工确认 → 岗位入库 → 香港筛选”这一条闭环。没有更改到岗天数、签证、邮件匹配或预填绑定。

## 当前行为

扩展从选定 JobPosting.description 和有限的可见岗位描述容器中，各筛取与地点有关的句子，合计至多三段、每段至多 150 字，总字段不超过 600 字。只传地点摘录，不传完整页面；HTML 不执行，URL 和常见跟踪参数从摘录移除。分别标记元数据正文或可见正文来源。超长或更多相关句被省略时标注摘录不完整。

工作台保留原 title、location、description，不拿推断地点覆盖原文。既有 description 字段保存摘录；读取岗位时派生 location_review，无数据库字段迁移。证据按页面地点标注、岗位标题、JobPosting.description、可见岗位正文或已存/手动摘录显示。来源标签是取文位置，不是对网站真实性或用户修改内容的认证。

“香港实习”现在分成两组：

- 正文明确支持香港实习的岗位，计入香港实地实习筛选。
- 地点冲突、培训/轮岗、远程/含糊或缺失的岗位，显示在“地点待复核（不计入香港实地实习）”。仍可查看原文与职位链接、收藏至台账；切回全部范围仍保留全部岗位。

明确“实习在外地、毕业后香港转正”标为地点冲突。必须异地培训/轮岗另行提示，不误写成实习主地点在外地；可选培训会注明是否必须需复核。海外总部本身不是实习地点，有明确香港实习正文时不会仅凭总部在海外判冲突。仅有香港标题/地点标注、转正或招聘办公室信息不够；没有正文或旧摘要接近截断上限时也需复核。

## 已验证

- 13 项 Python 地点测试：香港实习、异地实习与香港转正、中英文、总部、必须/可选轮岗、否定/未知地点、缺失、来源与限长、旧数据库与原字段保持、旧摘要截断。
- 扩展新增 3 项测试：摘录随草稿传递、结构化与可见正文分别标来源、HTML/链接惰性及截断提示。
- tests/fixtures/location-0.html 至 location-4.html 是全虚构本地网页。UI 集成测试读取这些本地网页的元数据，以虚构 HTTPS 页上下文运行真实捕获函数，再经 fragment、手动确认表单、本地 HTTP 与 SQLite，最终验证 2 条正文支持香港实习、3 条可见待复核，原地点仍为 Hong Kong。
- HTTPS/公开详情页约束没有放宽。测试中的 HTTPS 地址是模拟上下文，未访问真实招聘页面；本地 HTTP 验的是工作台服务，不冒充浏览器扩展实机。

## 限制与下一步

这是保守的有限规则，不是任意自然语言或全球地名理解。未支持的表达可能需要手动核对。仅检查截取到的摘要，不能证明原网页未漏掉其它安排；香港标记仍不是资格保证。已有公开源的摘要也会进入读取时判断，但这轮只对上述浏览器草稿闭环作专项验收，不承诺所有 ATS 模板均能提取完整地点证据。

无自动删岗、无自动提交、不连接真实邮箱、简历或凭据。Windows 与真实 Chrome/Edge 扩展仍待验收；本轮没有重做 v1.1.3 的预填绑定。维护方继续负责排障；候选 ZIP/TXT 仅留工作区，由主对话处理交付，不上传 Library 或另询审批。
