# v1.1.7 邮件时序与确认

负责方：原监督任务，继续唯一维护副本。只使用虚构邮件和临时数据库。

## 实际缺口与修复

旧版只有录入、通知和预约时间，没有实际提交申请的时间，唯一相同岗位名或编号即可能建议关联。现新增可选“实际投递时间（香港）”。用户填写真实提交申请的时间；不知道就留空。不会用 created_at、软件导入时间、面试时间或当前状态补值。

.eml 的 Date 是发送时间，不等同于收件时间。预览分别显示通知发送、预约发生、同公司记录的实际投递时间。Date 缺失或 -0000（未知时区）不推定为香港。手填时间按界面标注的香港时区解释，也接受显式 ISO 偏移。相对时限仍须核对：发送时间不能证明“收到后 48 小时”的起算点。

只有身份足够一致且时序明确才建议关联。邮件早于实际投递，即使编号一致也不预选；申请日期未知、邮件时间未知、同日只有日期精度，或没有合理旧申请，都保留复核。标题相似不同岗位不自动匹配。日期比较使用时区；只有日期的投递视为香港整日区间，非午夜的精确事件。

复核时默认不变更状态；用户选定记录并勾选复核，可只保存历史。要修改状态需明确选择。确认事务内再次检查预览时的投递记录快照，期间台账有变化则拒绝，要求重新预览；勾选复核不能绕过。

旧通知仍只入历史，不回退较新状态/安排。较晚提醒提及更早的面试时间但没有明确改期字样时只记录历史；明确改期可以移到更早日期。相同正文但发送时间不同的邮件分别保留历史；同正文同发送时间重复导入仍去重。兼容旧历史指纹（要求发送时间也相同），不重写原历史。

## 兼容与操作

启动时仅给 applications 增加 submitted_at TEXT NOT NULL DEFAULT ''。旧记录保留所有原字段与 ID，新增日期留空；不猜测历史。升级前用 v1.1.5 起的数据工具独立备份，保留旧安装。已有快照备份工具无变更。

在“投递追踪”编辑记录填写实际投递时间，然后重新导入虚构 .eml 并预览。核对发送、预约和实际投递三类时间；出现复核提示时手选记录，或保留待核实，不使用录入时间替代。预览期间修改台账后必须重做预览。

## 验证

Python 118、Node 32，共 150 项通过。新增 9 项测试覆盖旧邀请/晚申请、可信 ID 日期冲突、缺日期/同日精度、晚录入与早投递、跨时区边界、未知邮件时区、相似不同岗位、改期/旧邮件/较新旧安排提醒、重复与旧历史指纹；HTTP 覆盖复核只入历史、确认前数据变化阻断、无候选复核。原 MIME、多岗位、预填、岗位发现和备份回归保留。

归档 v1.1.6 合成库升级及新 ZIP 解压回归见成品 FINAL-VERIFICATION.txt。此轮没有访问真实邮箱/申请资料，也没有上传。Linux 自动化与本地 HTTP 通过；真实 Windows、Chrome/Edge 工具栏未实测。

限制：用户填写的投递时间及邮件 Date 需人工核实；规则不等同于真实投递凭证。缺日期时会多要求复核。以同正文同发送时间判重，不能区别该粒度内完全一样的两封信。下一验收点是 Windows 用虚构旧邀请和晚申请，确认不预选且不覆盖状态。
