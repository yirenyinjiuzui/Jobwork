# v1.1.3 候选：预填确认绑定原页面和表单

## 已有保障与本轮缺口

旧版已比较标签页 ID、完整 URL、字段元数据，并跳过已有值及敏感字段。同源切到另一 URL 会停填，不需要重复实现。但同一 URL 中将字段或表单替换成外观、标签、名称完全相同的新节点时，旧版会重新找到新节点并填写。新增回归先在旧逻辑复现：新节点收到 Fictional Candidate，本应保持空白。

Chrome 官方说明 activeTab 在同源导航后仍可能有效，所以授权有效不能证明是原页面：[activeTab 文档](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)。

## 本轮修复

- 每次扫描生成随机单次会话，只保存在扩展的当前文档隔离世界内存。绑定原 document、完整 URL、原字段节点及所属 form 引用；两分钟到期清理，重扫或使用后失效。
- 观察 DOM 是否发生变化，仅置失效标记，不复制页面文本或保存页面快照。字段、表单、岗位标题或其他 DOM 变化均保守地要求重新扫描。
- 切换标签页、页面隐藏或重载均使预览失效；切走再切回也不能沿用旧确认。弹窗最终查询期间收到切页事件，也不能恢复旧计划。
- 写入前核对整组选中字段。核对与原生 setter 在同一同步步骤中使用原节点，不重新定位其他表单。每项 input 事件之后再检查后续目标；页面改变时停止剩余写入，报告已写项数并要求重新扫描。已经触发的输入不能可靠回滚，用户须核对页面实际内容。
- 正常静止的本地练习页仍可填写；不覆盖已有值，不新增主机权限，不持久化个人字段值或其指纹，不自动提交，不填写签证、担保、工作许可。

策略偏保守：无关的 DOM 动画或计时文字也可能使预览失效。等待页面稳定后重扫；持续变化的页面请手填。此轮不尝试理解任意 SPA 内部状态、跨站 iframe 或封闭 shadow DOM。

## 可选的纯本地实机复现

测试夹具在 `tests/fixtures/form-binding.html`，没有账号、真实身份、外部资源或提交动作。项目根目录另开终端运行：

```text
python -m http.server 8767 --bind 127.0.0.1 --directory tests/fixtures
```

浏览器访问 `http://127.0.0.1:8767/form-binding.html`，加载本版 extension 并仅导入 demo-profile.json。正常对照：刷新，不点击页面的变更按钮，扫描并确认，姓名/邮箱可填，签证和工作许可留空。

变化场景：点击夹具的 URL、SPA 或 heading 按钮，在八秒计时内打开扩展完成扫描，等待变化后再确认，必须停填或弹窗关闭后要求重扫。URL 场景打开同源 B；SPA 场景 URL 不变但更换岗位及同形表单；heading 场景仅改岗位标题。另可扫描后切到别的标签，再切回，旧预览不能继续使用。

中途变化：先点击 Replace remaining form on first input，再扫描并填写。第一个 input 事件会替换整个表单，后续字段不得写进新表单；提示已写项数与停填，实际页面可能显示新空表单。该夹具用于后续实机复核，本轮未在真实浏览器执行成功。

维护由助手继续负责。只保留本地候选 ZIP/TXT，不上传 Library，不改变 v1.1/v1.1.1/v1.1.2 既有包。地点与到岗时间不在本轮范围。
